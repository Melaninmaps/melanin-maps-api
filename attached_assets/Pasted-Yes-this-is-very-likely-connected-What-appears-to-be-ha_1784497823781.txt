Yes—this is very likely connected.

What appears to be happening is that the system recognizes your email as belonging to an existing user record, but the authentication method you are using does not match the credentials attached to that record. For example:

* Your admin user may originally have been created through phone login or another provider.
* The same email is stored on that user record.
* Email login sees the email exists, but there may be no usable password hash attached to that same user.
* Creating a second account with the email is blocked because the email already exists.
* Admin access is tied to the original user ID, so a new account would not preserve your history or permissions.

Email forwarding does not cause the problem. You can keep using the same email address where your messages are forwarded. The solution is to **link email/password authentication to your existing user ID**, not create another user.
