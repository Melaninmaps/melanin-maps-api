Founder testing uncovered multiple launch-blocking defects in the current mobile build.

### 1. Phone login works, but sends a paid SMS code for every login

Current behavior:

* A member can create an account using their phone number.
* Every later login requires a new SMS verification code.
* There is no option to create or use a password.

This may be intentional passwordless authentication, but it creates an SMS charge every time a member logs in and is not the experience I want.

### Required product behavior

Please assess and implement the safest low-cost model:

* SMS code establishes and verifies the phone number during account creation.
* The member should remain signed in on that trusted device through persistent sessions.
* Routine reopening of the app must not trigger another SMS.
* Provide a secure login credential for returning access, such as:

  * password or app PIN; or
  * another approved low-cost authentication method.
* SMS should be reserved primarily for:

  * initial phone verification;
  * account recovery;
  * suspicious-device verification;
  * deliberate sign-in on a new device.

Do not weaken security merely to reduce SMS costs. Present the proposed authentication model before implementation if it changes the account architecture.
