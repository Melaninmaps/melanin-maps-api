- therefore, the latest audited commit does not appear to be running in

══════════════════════════════════════════════════════════════

   - total connections
   - active connections
   - idle connections
   - waiting requests
   - maximum pool size
   - process ID
   - restart count

2. Instrument every database checkout and release with:
   - route or operation name
   - request ID
   - checkout timestamp
   - release timestamp
   - duration held
   - success, timeout, or error
   - whether the client was released

3. Audit every use of:
   - pool.connect()
   - client.query()
   - transactions
   - streaming queries
   - background jobs
   - health checks
   - session renewal
   - notification polling
   - scheduled jobs

4. Confirm every pool.connect() uses a guaranteed finally block:

   const client = await pool.connect();
   try {
     // database work
   } finally {
     client.release();
   }

5. Search for:
   - missing client.release()
   - early returns before release
   - exceptions before release
   - transactions without COMMIT or ROLLBACK
   - multiple pool instances
   - pools created per request
   - duplicated background workers
   - health endpoints opening connections unnecessarily
   - retry loops that create new clients
   - long-running or abandoned queries

6. Confirm the application creates only one intended pool per process.

7. Add temporary connection acquisition stack tracing or equivalent
   diagnostic attribution so every unreleased client can be tied to its
   originating operation.
