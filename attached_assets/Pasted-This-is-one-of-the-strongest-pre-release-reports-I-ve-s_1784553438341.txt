# 1. Verify the production waitlist endpoint (5 minutes)

This is the only item I would personally verify in a browser because it directly affects your launch experience.

Visit:

**[https://api.mappingwithmelanin.com/api/waitlist/count](https://api.mappingwithmelanin.com/api/waitlist/count)**

If it returns JSON like:

```json
{
  "count": ...,
  "cities": ...
}
```

then we're done.

If it doesn't, I'd pause just long enough to correct the production routing before promoting the waitlist publicly.

---

# 2. Check Google Play upload-key status

As the report says, only you can see the current Play Console banner.

If it says:

> Upload key reset approved

then Android submission can happen immediately after the build.

If it says:

> Pending

then build anyway and keep the AAB ready.

---

# 3. Freeze the build

This is the one recommendation I'd add that isn't in the report.

Once you start the EAS builds:

* no feature additions
* no prompt edits
* no UI tweaks
* no styling changes
* no dependency updates

Unless Apple or Google rejects something, this becomes your **release candidate**.

From here until review, every change increases risk.
