A safer implementation would read the response as text first, then attempt JSON parsing:

```ts
const response = await fetch(url, options);
const contentType = response.headers.get("content-type") ?? "";
const rawBody = await response.text();

let data: unknown = null;

if (rawBody) {
  try {
    data = JSON.parse(rawBody);
  } catch {
    console.error("Reset response was not JSON", {
      status: response.status,
      contentType,
      bodyPreview: rawBody.slice(0, 100),
    });

    throw new Error(`Non-JSON response: HTTP ${response.status}`);
  }
}
```

Then the interface can show something specific such as:

```text
Reset failed: HTTP 502
```

or:

```text
Reset service returned an unexpected response.
```

At this point, **one internal diagnostic build is justified** because the live server route works through direct testing, but the installed app’s reset request fails inside the device. The build should diagnose only the login/reset client flow and must not touch your closed-testing release.
