### What Replit should investigate next

The frontend is correctly sending chat requests with `credentials: "include"`, and the user session remains active elsewhere in the product. The remaining problem is therefore likely **inside the Kinfolk chat route after authentication**, rather than the browser’s stale token alone.

Replit should add temporary server-side request tracing to `/api/kinfolk/chat` and capture, for one failing request: whether cookie authentication succeeds, whether the Kinfolk session is created/found, whether the AI provider call begins, the provider response status/body, and the final exception returned to the UI. The UI currently hides all of that behind the same generic error, so this single trace will isolate the real failure quickly.

The correct release gate is: a cleanly authenticated tester must receive successful answers for **one Phuket itinerary question, one Philadelphia recommendation, and one basic question** before Kinfolk is considered ready for testers.
