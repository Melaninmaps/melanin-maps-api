From your screenshot, the Profile page is rendering **“No saved places yet”** even though you have been actively saving/using businesses. That means one of three things is happening: the save action is not persisting, the Profile page is reading from the wrong table/API, or the saves exist but are not associated with the correct production user/account.

Kinfolk should **not depend only on Saved Places**, but it absolutely should use them. Think of the personalization stack like this:

**Explicit signals:** Saves, follows, stated preferences, Library topics, profile choices.
**Behavioral signals:** Searches, clicked businesses, map interactions, check-ins, reviews, Vibes/THE REAL selections, event activity.
**Context signals:** Current location, trip destination, current conversation, time/occasion.
**Community intelligence:** What similar members recommend, trusted community signals, Cultural Ambassador content, safety/history data.

So if you save AMINA, Kinfolk should eventually understand that as stronger evidence than simply viewing AMINA once. But it should not conclude, “Teianna only likes Southern food.” It accumulates evidence rather than replacing what it already knows.
