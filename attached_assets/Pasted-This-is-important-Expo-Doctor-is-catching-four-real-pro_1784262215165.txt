## What Replit needs to fix

### 1. Invalid `app.json` fields

Doctor says these fields are not valid where they currently appear:

```text
newArchEnabled
privacyPolicyUrl
splash
android.googleMapsApiKey
android.splash
```

This does **not necessarily mean you must permanently lose your splash screen, privacy-policy URL, Google Maps key, or architecture setting**. It means they are being declared in a format or location that Expo SDK 57’s current schema does not accept.

This is especially relevant because custom native behavior should generally be applied through valid Expo app configuration or config plugins during Prebuild—not by leaving unsupported fields in `app.json`. ([Expo Documentation][2])

Replit should:

* inspect whether the root of `app.json` is structured correctly under `"expo"`,
* compare every field against the SDK 57 app-config schema,
* migrate unsupported native settings into valid config plugins,
* and rerun `npx expo config --type public` to verify the resolved configuration.

### 2. Remove direct `@expo/config-plugins`

The project directly installs:

```text
@expo/config-plugins
```

Expo Doctor says this should not be a direct dependency. Replit should remove it and update any custom plugin code to import from:

```javascript
expo/config-plugins
```

This is particularly significant because the Google Maps Podfile problem appears to involve custom config-plugin behavior. A plugin using an unsupported direct package may be part of the instability.

### 3. Install the missing `expo-asset` dependency

Doctor explicitly reports:

```text
Missing peer dependency: expo-asset
Required by: expo-audio
```

The prescribed fix is:

```bash
npx expo install expo-asset
```

Native peer dependencies need to be installed directly because an app may work in Expo Go yet crash or fail in an actual standalone build when one is missing. Expo’s package guidance uses `npx expo install` so the dependency version matches the active SDK. ([Expo Documentation][3])

### 4. Resolve the duplicate React versions

This may be the most serious dependency issue:

```text
react@19.2.3  — inside the mobile project
react@19.1.0  — in the parent workspace
```

A native app should not resolve two React copies. That can cause unpredictable bundling, hooks errors, native module resolution problems, and build inconsistencies.

The paths suggest your mobile app is inside a larger pnpm workspace or monorepo:

```text
node_modules/react
../../node_modules/react
```

Replit needs to align the entire workspace on one Expo-compatible React version and regenerate the lockfile. Expo’s monorepo documentation specifically recommends using dependency resolutions when necessary to force one compatible React version across a workspace. ([Expo Documentation][4])
