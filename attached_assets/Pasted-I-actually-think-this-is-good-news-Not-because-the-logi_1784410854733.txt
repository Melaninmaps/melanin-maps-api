### 5. Generic Error

> "Unable to connect. Check your internet connection."

This is especially important.

That error is almost always a **generic frontend error**, not necessarily a real network problem.

It usually means:

> "The frontend expected a response but didn't receive a successful one."

It **doesn't** necessarily mean the internet is down.

# Why I don't think these are separate bugs

All three authentication methods failing simultaneously tells me something.

They all eventually depend on the same backend.

Whether you log in by:

* email
* phone
* Apple

they eventually need to:

* create a session
* set cookies or tokens
* read the user
* return authenticated state

If all fail...

I suspect the shared layer is failing.

## My recommendation

Let's make this our rule for the rest of launch:

> **No implementation without explanation.**

If Replit tells us, "We changed X," our next question should be:

> **"Why does changing X resolve the observed behavior, and what evidence proves it?"**

I actually think that's one of the biggest lessons from the twelve audits. We've moved from accepting "it's fixed" to expecting a clear explanation, supporting evidence, and an end-to-end verification. That discipline is exactly what's going to help you launch with confidence rather than hope.
