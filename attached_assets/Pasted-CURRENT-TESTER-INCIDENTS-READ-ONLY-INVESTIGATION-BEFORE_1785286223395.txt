D. MAP LOCATION LOOP
══════════════════════════════════════════════════════════════

Investigate why the Map remains in a continuing “finding location” state.

Review:

- permission request flow;
- foreground location permission status;
- denied/restricted/undetermined states;
- getCurrentPosition timeout;
- location watcher creation and cleanup;
- repeated effects or render loops;
- loading-state reset;
- error handling;
- cached last-known location;
- simulator/device behavior;
- app background and foreground transitions;
- whether a watcher is created more than once;
- whether the Map waits for location before loading businesses or
  heritage data;
- whether location denial blocks manual browsing;
- whether coordinates are ever null, undefined, stale, or 0/0.

Required user behavior:

- Location must be optional for manual map browsing.
- The app must not spin indefinitely.
- After a reasonable timeout, show a clear message and choices such as:
  Retry, Browse Manually, Enter a City, or Open Settings.
- Denied permission must not repeatedly prompt during the same session.
- The Map should use a safe last-known or default browsing region when
  appropriate.
- All location subscriptions must be cleaned up.
- No location error should close the app.
- No 0,0 “Null Island” pins may be created.

Test at minimum:

- permission allowed;
- permission denied;
- permission set to Never;
- location services disabled;
- poor GPS signal;
- no network;
- slow response;
- app backgrounded during lookup;
- app reopened;
- switching Wi-Fi/cellular;
- manual city search without location.

State whether the defect is in the submitted mobile binary and whether a
new EAS build is required.
