## Why the validation branch is useful

`eas update` generates the update bundle before uploading it. Publishing to an unlinked validation branch confirms that Expo can bundle the exact clean commit without sending it to Build 94 users. Production builds receive updates through their configured channel, so an unlinked branch will not affect your production TestFlight build. ([Expo Documentation][1])

Do not use the suggested command with only:

```bash
eas update --branch staging
```

unless Replit first proves that `staging` is not linked to a tester-facing channel. A uniquely named branch such as `pool-fix-validation` is safer.
