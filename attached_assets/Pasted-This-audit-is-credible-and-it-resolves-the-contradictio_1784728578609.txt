This audit is credible and it resolves the contradiction.

The key point is:

**`HBCU — 0` was not caused by the last map UI change. It happened because the cultural-sites request failed while the database pool was exhausted, and the app silently gave up.**

That explains why:

* login failed,
* businesses failed,
* cultural sites failed,
* but `/api/healthz` still worked.

It also explains why the same UI could show **44** in one session and **0** in another without a code difference.

## What this means now

The rollback was not harmful, but it did not fix the real weakness:

```ts
if (res.ok) {
  setCulturalSites(data.sites ?? []);
}
```

When `res.ok` is false:

* no error appears,
* no retry occurs,
* no cached data is kept,
* the empty state looks like “there are zero HBCUs.”

That is dangerous because a temporary backend outage becomes misleading content.
