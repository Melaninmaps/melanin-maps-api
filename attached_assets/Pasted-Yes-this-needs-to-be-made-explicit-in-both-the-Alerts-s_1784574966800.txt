Yes—this needs to be made explicit in both the **Alerts settings** and the app’s permission logic.

The three choices mean different things:

* **Never**: the app cannot use the person’s location.
* **While Using the App**: the app can use location when the app is open, and in limited background situations if location activity is already running.
* **Always**: the app may receive certain location events even when the app is not open, including some region, visit, or significant-location-change events. Apple recommends requesting this only when it is truly necessary and after the user understands the benefit—not automatically at first launch. ([Apple Developer][1])

## What this means for Mapping With Melanin™

A user can still receive **general push notifications** with location set to Never or While Using. For example:

* a saved business posts an update;
* an event time changes;
* a group has a new message;
* an alert was issued for a city the user manually follows.

But alerts that depend on knowing the user has entered or is near a specific area may require **Always** location access, depending on how Replit implemented them.

Examples:

* “You are approaching an area with a recent safety alert.”
* “A road closure was reported near your current route.”
* “A saved place nearby has a new verified safety update.”

If the app only checks location while open, **While Using** may be enough. If it must warn the user while the app is closed or terminated, **Always** may be needed for supported background location services. ([Apple Developer][1])

## Recommended user experience

Do not ask for Always at first launch.

Use this progression:

1. Ask for **While Using the App** when the user first opens the map, directions, nearby discovery, or submits location-based intel.
2. In Alert Settings, explain that optional background alerts require additional access.
3. Let the user intentionally enable:

> **Nearby alerts when the app is closed**

Only then should the app explain and request Always access.

This follows Apple’s recommendation to request location in context, immediately before the feature needs it. ([Apple Developer][1])

## Suggested warning in Alerts Settings

### Nearby Safety Alerts

> Receive alerts about verified safety updates, road closures, and other activity near your location.

Then show the current permission:

> **Location access: While Using the App**

And explain:

> With “While Using,” nearby alerts are available when Mapping With Melanin™ is open. To receive eligible location-based alerts when the app is closed, you may choose “Always Allow” in your device settings.

Buttons:

* **Keep While Using**
* **Enable Background Alerts**
* **Not Now**

Also include:

> You can still receive alerts for saved places, followed cities, businesses, events, and communities without sharing your background location.

That prevents users from feeling forced to grant Always access.

## Privacy rule

Background location should never be required simply to use the app.

The user should still be able to:

* browse businesses;
* search cities;
* use KinfolkAI;
* follow locations manually;
* receive non-location-specific alerts;
* report something using a location they enter themselves.

Also, “Always” should not mean continuous tracking unless the feature genuinely requires it. The app should use the least intrusive location service necessary and clearly state what is collected, when, and why.
