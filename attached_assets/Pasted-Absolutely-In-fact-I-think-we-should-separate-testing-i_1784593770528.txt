# One thing I want Replit to start doing

Right now Replit verifies functionality.

I also want it to verify **experience**.

For example, don't just test:

> Map loads.

Also test:

> If a new Philadelphia user opens the app for the first time, do they immediately see something interesting to explore?

Not just:

> Kinfolk responds.

Also ask:

> Does Kinfolk sound like someone you'd actually want to talk to?

Not just:

> Search returns results.

Also ask:

> Would a first-time user understand what they can search for?

These are harder to automate completely, but they encourage the team to think beyond whether code executes.

I also have one request for the family testing. Rather than giving everyone the same checklist, have each person use the app differently. For example, ask one person to act like they're moving to Philadelphia, another to find a restaurant for a date night, another to report a neighborhood concern, another to discover local history, and another to explore Kinfolk without any instructions. That diversity of use cases will reveal different kinds of issues than if everyone simply follows identical test steps.

I think that combination—Replit's engineering verification, your family's real-world use, and a final experience review—will give you far more confidence in each release than relying on any single testing approach.
