The new approach is reasonable, but Replit’s interpretation needs one correction:

> **A red “MapKit init…” badge does not automatically prove a native binary problem.**

It could also mean:

* the `MapView` never mounted,
* its container still has zero height or width,
* another React view covers it,
* the component unmounted before `onMapReady`,
* or a JavaScript/rendering error prevented initialization.

So a red badge would justify deeper inspection before deciding Build 95 is required.

## After Replit publishes it

1. Force-close the app.
2. Reopen and wait 15–20 seconds.
3. Force-close again.
4. Reopen.
5. Open the Map tab.
6. Take a screenshot showing the whole map and diagnostic badge.

Interpret it as follows:

* **Green `MapKit ✓`, tiles visible:** Map fixed.
* **Green `MapKit ✓`, screen still black:** MapKit initialized; a React overlay, styling, map type, or covering component is blocking the visible tiles.
* **Red `MapKit init…` with `0×0`:** layout/container problem, likely OTA-fixable.
* **Red with nonzero dimensions:** inspect runtime/native logs and MapView configuration before deciding another build is necessary.
* **No badge:** the OTA did not apply or `FullMapView` is not the screen being rendered.

This is the correct next diagnostic step, and it should remain a single-purpose OTA.
