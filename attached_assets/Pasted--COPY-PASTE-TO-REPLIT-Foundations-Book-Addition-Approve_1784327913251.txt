# Foundations Book Addition — Approved Slide & Deck Registry

**Status: Review Mode. Nothing should be implemented yet.**

Yes, the Foundations Book should catalog every **approved slide, deck, and reusable message** across Mapping With Melanin™.

However, this should not become an uncontrolled system that automatically rewrites every presentation whenever one slide changes.

The correct model is:

> **One approved source of truth, with controlled propagation into individual decks.**

The Foundations Book should document what is approved, where it is used, and whether an update should be applied elsewhere. Replit should propose affected updates first and wait for explicit authorization before modifying other decks.

## 56. Controlled Propagation Rule

When an approved master slide changes, Replit must:

1. Identify every deck containing that slide or a related variation.
2. Produce an **Impact Report**.
3. Show:

   * which decks are affected;
   * which slide numbers are affected;
   * whether the change is copy, visual, factual, legal, or structural;
   * whether the target deck uses the exact master or an audience-specific variation;
   * any risk of breaking layout or storytelling flow.
4. Propose the updates.
5. Wait for explicit authorization.
6. Apply only the approved updates.
7. Verify every affected deck after implementation.
8. Update the registry and changelog.

No automatic cross-deck edits should occur without approval.

---

## 57. Cross-Deck Update Command

When I explicitly authorize a change across presentations, the implementation request should specify:

```text
Please implement this approved master-slide update across every registered deck that uses it.
```

That authorization means Replit should:

* update the master slide;
* update every approved linked instance;
* preserve audience-specific variations;
* preserve slide order unless explicitly changed;
* preserve deck-specific pacing;
* verify every affected deck;
* report all files and slides changed.

Without that explicit authorization, Replit should update only the named deck or file.

---

## 58. Slide Change Impact Report

Before any approved slide is changed across multiple decks, provide:

### Proposed Master Change

* Current approved copy or design
* Proposed copy or design
* Reason
* Expected improvement

### Affected Decks

* Deck name
* Slide number
* Exact or adapted instance
* Required adjustment
* Risk level

### Excluded Decks

List decks that contain a similar slide but should not be changed, with the reason.

### Approval Required

No propagation occurs until explicitly authorized.

## 63. Presentation Source-of-Truth Rule

The Foundations Book and its registries become the source of truth for approved presentation content.

Individual decks should not become isolated copies with undocumented changes.

Every deck should identify:

* the Foundations Book version it follows;
* the Storytelling Standards version;
* the Color System version;
* the Typography System version;
* the slide registry version;
* the date last synchronized.

Example footer or metadata:

```text
MWM Foundations v1.0
Storytelling Standards v1.0
Presentation Registry v1.0
Last synchronized: TBD
```

This metadata may remain internal rather than visible to audiences.

# Important Implementation Principle

The Foundations Book should catalog and govern every approved slide, but it should **not contain every full slide visually within the main written narrative**.

That would make the book too large and difficult to maintain.

Recommended approach:

### Main Foundations Book

Contains:

* the standards;
* the registry tables;
* selected signature slides;
* links or references to approved deck files;
* visual examples;
* protected brand messages.

### Presentation Appendix or Digital Slide Library

Contains:

* full approved slide thumbnails;
* deck-by-deck indexes;
* component previews;
* source links;
* archived versions.

This gives us a complete record without making the main Foundations Book unreadable.

# Required Replit Behavior Once This Is Implemented

When any slide or approved message is changed, Replit should automatically perform an **audit**, not an automatic edit.

The audit should identify:

* every related deck;
* every affected slide;
* every related copy block;
* every audience-specific variation;
* every component or file that may require review.

Then Replit must ask:

> Do you want me to apply this approved change across all affected decks, only selected decks, or only the current deck?

No cross-deck edits occur until I answer.

# Recommendation

Yes, build this registry into the Foundations Book.

It will prevent:

* inconsistent messaging;
* old slides continuing to circulate;
* visual drift;
* accidental rewrites;
* trademark inconsistencies;
* duplicate versions;
* different audiences receiving conflicting information;
* Replit updating one deck but forgetting the others.

It will also make future updates much easier because every approved slide, phrase, visual, and deck will have a documented place in the system.
