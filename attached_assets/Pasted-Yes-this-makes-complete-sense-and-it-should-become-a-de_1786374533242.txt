Yes — this makes complete sense, and it should become a **design-system rule**, not a one-off cleanup.

The distinction is:

**MWM-authored / platform-generated visual language → polished Mapping with Melanin™ iconography.**
**User-authored expressive content → normal native emoji are allowed.**

So if a community member writes, “I love this house 🏠,” their 🏠 stays the normal Apple/Android emoji. But if MWM displays **Top Realtor**, **Home Services**, a housing badge, a search chip, a category icon, a Kinfolk recommendation card, or a platform-generated indicator, the house should be the **MWM polished gold house icon**, not 🏠.

I’ll treat that as a standing Mapping with Melanin design requirement in our work going forward. Since persistent memory controls aren’t available to me in this turn, I don’t want to falsely claim I’ve written it into a permanent memory store—but I will carry it forward in this project context.
