# Ship Priority Directive

**Rule:** Every decision, suggestion, and step must optimize for the fastest path to a published, high-quality app. No exploratory back-and-forth, no dead ends, no "try this and see."

**Why:** User has demand for the app now and has experienced repeated delays. Time lost to wrong turns is unacceptable.

**How to apply:**
- Know the full sequence of steps before starting any multi-step process — confirm prerequisites exist before directing the user to do anything.
- If a step requires a prior step to be complete first, lead with that blocker immediately.
- Prefer definitive instructions over "try X and send me a screenshot."
- For App Store submissions: always check Apple's current requirements before guiding (binary must exist before IAPs can be attached, etc.).
